## 这一片为什么存在

用户 2026-08-04 报的 bug:在书里打完一轮结算、点 `>` 继续,然后在打字页按左箭头 `<` 往回翻,**书架上的进度跟着变小**;一路翻回开头,进度直接清零。

根因在 `frontend/src/ts/books/book-session.ts:136`:

```ts
LocalBooks.setProgress(book.name, book.progress + direction * step);
```

`progress` 一个字段兼两个身份 ——「我现在在书里的哪个位置」和「我总共打完了多少」。翻页即改成绩。用户同时提出的白/灰配色、缺口胶囊、回到进度三项需求,恰好都要求把这两件事拆开,所以合成一个里程碑做。

## 数据模型(M3a 的全部内容)

`frontend/src/ts/books/local-books.ts` 的 `StoredBookSchema` 增两个字段,`progress` 保留但语义收窄为**光标**:

```ts
progress: number      // 光标:这一轮从第几个词开始。左右箭头只动它
done: [number, number][]     // 已结算的词区间 [start, end),有序、相邻合并
skipped: [number, number][]  // 用户 ✗ 掉的缺口,同上
```

保留 `progress` 这个名字而不是改叫 `cursor`,是因为它是上游 `customTextLong` 的字段名,`test/custom-text.ts` 与 `applyRound()` 都在读;改名要动的面比收益大。**注释里必须写清它现在只是光标。**

派生量(纯函数,不落盘):

| 名字 | 定义 |
|---|---|
| `doneWordCount(book)` | `done` 各段长度之和 → 白字数 |
| `getProgressPercentage(book)` | `doneWordCount / wordCount` —— 改的就是这一行 |
| `frontier(book)` | `done` 最后一段的 `end`;没有则 0。**只增不减** |
| `gaps(book)` | `[0, frontier)` 里既不在 `done` 也不在 `skipped` 的空洞 |

写操作:

- `settleRound(name, start, end)` —— 结算时调用:并入 `done`、从 `skipped` 里挖掉这一段、光标置为 `end`
- `dismissGap(name, [start, end])` —— ✗:并入 `skipped`
- `setCursor(name, pos)` —— 箭头 / 点胶囊 / 回到进度。**不碰 `done`**
- `resetProgress(name)` —— 清空 `done`、`skipped`,光标归零

区间工具(`mergeRange` / `subtractRanges` / `invertRanges`)写成模块内纯函数,好单测。

**迁移**:`migrateShelf` 里老书 `progress: N` → `done: N > 0 ? [[0, N]] : []`,光标保持 `N`。线性读到 N 的书语义完全等价,不丢任何人的进度。`done` 缺失的新旧混合数据同样走这条。

## 分片

### M3f2 — 模块边界(blocks)+ 续打落点 ⬜

**M3g 的前置**。spec 见 `WORKORDER.md`「模块(block):每一轮的边界要存下来」。用户实测报的 bug:上一轮没打满就停,再按键却从那半块的**开头**重打,而不是从没打完的地方接着打。

- `local-books.ts`:新增 `blocks: { range: Range, complete: boolean }[]`(按结算顺序,**不合并**);`settleRound` 多收一个 `complete` 参数并追加一条;`resetProgress` 清空;老书迁移给 `[]`(老数据没有边界可考,一律当不完整 → 续打落在 leftoff,不会让人重打)
- `test-logic` 结算处判 `complete`:词数轮 = 打满 N 词(`!getBailedOut() && limitMode === "word"` 那条路已经算出来了);时间轮 = 时间走完(没 bail out)
- `getLastFinishedStart` 拆成两支:最后一块 complete → 块开头;不完整 → 块的 `end`(leftoff)
- `getRetypeRange` 改成认**完整块**:光标落在某个 complete 块的开头/内部 → 重打范围 = 那一块;落在不完整的尾巴上 → 不是重打,是接着读
- 单测:两种落点、切字数档不改变块范围、老书迁移、块不合并

### M3g — 打字页:回看模式 + 重打徽章 ⬜

> 依赖 **M3f2**。

- **回看态**:窗口全落在 `done` 内且未开打 → 不计时、`#words` 显示整段(解除三行限制)、容器可上下滚动;敲字母键切入重打(正常判定流)
  - 白/灰规则见 `WORKORDER.md`「白 / 灰只回答一个问题」。**开打即转灰底**已在 M3f 收尾时落地(`#words.typing` 抑制 `.settled` 白,`onTestStart` 加、`onTestRestart`/`onTestFinish` 去),M3g 只需保证回看态不加这个 class
- **徽章**:右上角(书名指示条一带)每条重叠记录一个数字;点开:没打完 → **前白后灰**(白 = 上次打到哪)+「接着继续」(pour 剩余词,`activeMs` 续算,time 模式按剩余秒倒数);打完 → **整段全白**、只读 + 「YYYY-MM-DD HH:mm:ss → HH:mm:ss · 用时 Ns」+ 「战绩」按钮进结算页(用存的 stats 重建;每秒曲线没存全就省略图,别造假数据)
  - 「只读」不许用灰表示(灰已经归"没打过"了),用别的方式:不接受输入 + 明说这是第几次的记录
- **段尾掐断**:重打中打到窗口末词 → 立即按本次结算、toast「已到这一段结尾,本次到此结算」
- 风险:结算块是 M2f/M3a 两次修过的地方,`completedWords` 算法原样保住;三行限制/滚动要动 `test-ui.ts` 的行高逻辑,先实地读再动
