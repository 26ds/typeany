## 这一片为什么存在

用户 2026-08-04 报的 bug:在书里打完一轮结算、点 `>` 继续,然后在打字页按左箭头 `<` 往回翻,**书架上的进度跟着变小**;一路翻回开头,进度直接清零。

根因在 `frontend/src/ts/books/book-session.ts:136`:

```ts
LocalBooks.setProgress(book.name, book.progress + direction * step);
```

`progress` 一个字段兼两个身份 ——「我现在在书里的哪个位置」和「我总共打完了多少」。翻页即改成绩。用户同时提出的白/灰配色、缺口胶囊、回到进度三项需求,恰好都要求把这两件事拆开,所以合成一个里程碑做。

## 数据模型(M3a 的全部内容)

`frontend/src/ts/books/local-books.ts` 的 `StoredBookSchema` 增两个字段,`progress` 保留但语义收窄为**光标**:

```ts
progress: number      // 光标:这一轮从第几个词开始。左右箭头只动它
done: [number, number][]     // 已结算的词区间 [start, end),有序、相邻合并
skipped: [number, number][]  // 用户 ✗ 掉的缺口,同上
```

保留 `progress` 这个名字而不是改叫 `cursor`,是因为它是上游 `customTextLong` 的字段名,`test/custom-text.ts` 与 `applyRound()` 都在读;改名要动的面比收益大。**注释里必须写清它现在只是光标。**

派生量(纯函数,不落盘):

| 名字 | 定义 |
|---|---|
| `doneWordCount(book)` | `done` 各段长度之和 → 白字数 |
| `getProgressPercentage(book)` | `doneWordCount / wordCount` —— 改的就是这一行 |
| `frontier(book)` | `done` 最后一段的 `end`;没有则 0。**只增不减** |
| `gaps(book)` | `[0, frontier)` 里既不在 `done` 也不在 `skipped` 的空洞 |

写操作:

- `settleRound(name, start, end)` —— 结算时调用:并入 `done`、从 `skipped` 里挖掉这一段、光标置为 `end`
- `dismissGap(name, [start, end])` —— ✗:并入 `skipped`
- `setCursor(name, pos)` —— 箭头 / 点胶囊 / 回到进度。**不碰 `done`**
- `resetProgress(name)` —— 清空 `done`、`skipped`,光标归零

区间工具(`mergeRange` / `subtractRanges` / `invertRanges`)写成模块内纯函数,好单测。

**迁移**:`migrateShelf` 里老书 `progress: N` → `done: N > 0 ? [[0, N]] : []`,光标保持 `N`。线性读到 N 的书语义完全等价,不丢任何人的进度。`done` 缺失的新旧混合数据同样走这条。

### M3b — 书卡:白字占比 + 缺口胶囊 ✅(2026-08-04)
